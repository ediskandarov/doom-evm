# Phase 1 interface freeze v1

Integrator-owned, 2026-10-09. Extends the v0 interfaces without changing Frame, resource identity, contexts, or the abstract Doom adapter. Implementation work may start against this contract. Changes require an explicit integrator decision recorded here.

## Numeric and table modules

`library M_Fixed` in `src/doom/m_fixed.sol`: internal pure `FixedMul(int32 a,int32 b) returns(int32)`, `FixedDiv(int32 a,int32 b) returns(int32)`, `FixedDiv2(int32 a,int32 b) returns(int32)`. Preserve original control flow and signed narrowing. Invalid direct division gets an explicit custom error, not a successful fabricated result. Original defined binary64 results must match; using integer division requires a proof for the supported domain and native comparisons. Undefined C cases are separate from equivalence claims. The integrator approves a deterministic INT_MIN absolute-value policy only after the oracle reports actual behavior and the port documents the choice.

`library Tables` in `src/doom/tables.sol`: internal pure `finesine(uint256 index) returns(int32)` (10240 entries), `finecosine(uint256 index) returns(int32)` (8192 entries, alias sine index+2048), `finetangent(uint256 index) returns(int32)` (4096), `tantoangle(uint256 index) returns(uint32)` (2049), `SlopeDiv(uint32 num,uint32 den) returns(uint32)`. Reject out-of-bounds lookups; do not silently mask indexes. Preserve upstream constants including FINEANGLES=8192, FINEMASK=8191, ANGLETOFINESHIFT=19, SLOPERANGE=2048 and ANG45/90/180/270. Preserve unsigned 32-bit wrapping of SlopeDiv's num<<3. Static bytes may be generated only from pinned `tables.c` initializers, never host trigonometric functions. Table hashes are SHA-256 over each complete sequence of little-endian 32-bit words; cosine hashes the sine slice.

## Native oracle and vector contract

`schemas/vectors-v1.schema.json` defines numeric and geometry vectors. Metadata includes exact upstream, C compiler version/target/flags, source/harness/patch hashes, integer and floating semantics. WAD-independent vectors use all-zero wadSha256 and scope `numeric` or `geometry-synthetic`; actual map vectors use nonzero WAD SHA and scope `geometry-wad`. Each row has function, inputs (ordered integers), outputs (ordered integers), status (`ok`, `error`, `undefined`) and a note. Non-ok rows have empty outputs. Signed parameters are int32; unsigned parameters uint32. Semantic validation enforces signatures rather than relying solely on array item bounds.

Numeric inputs: FixedMul/FixedDiv/FixedDiv2=[a,b], SlopeDiv=[num,den]; one output for ok. Geometry: R_PointOnSide=[x,y,node.x,node.y,node.dx,node.dy]; R_PointToAngle2=[viewx,viewy,x,y]; R_PointInSubsector=[x,y], outputs=[subsectorIndex] with map identity. Trace rows may use `BSPPath`, inputs=[x,y], outputs=node indexes followed by raw NF_SUBSECTOR child. Geometry implementation belongs to the C harness in Phase 1; no Solidity renderer module is authorized yet.

Build the original C units or mechanically extract named function bodies with asserted source hashes and exact extraction records; hand-transcribed replacement algorithms are not the oracle. Baseline compiler: installed Apple clang 17.0.0 (clang-1700.0.13.5), arm64-apple-darwin24.6.0, `-std=c99 -O2 -fwrapv -fno-strict-aliasing -ffp-contract=off -fno-fast-math`. Record full effective flags. Check O0/O2 stability and use sanitizers to identify undefined input domains. Assert 32-bit int, 64-bit long long and IEEE binary64 assumptions. Native portability changes must be explicit, hashed, and separate from original algorithm bodies. I_Error is intercepted as an error outcome; 0/0 and abs(INT_MIN) cannot be called defined original-C results. Pin this compiler profile in harness metadata and reject silent drift in verification; other hosts require an explicitly recorded profile.

The reference stream can generate Solidity fixture source in `test/fixtures/reference/` for Foundry imports, avoiding FFI or changing fs permissions. Include deterministic edge and seeded random vectors. A reproducibility check regenerates and compares semantic outputs and verifies all source identities. Golden infrastructure records camera/settings with the v0 reference metadata; pixel diff tooling reports exact mismatch count/coordinates and dimensions. No Phase 1 artifact may claim an actual renderer golden.

## Resource packing and map records

Keep `resource-bundle-v0`: every input directory entry is repacked contiguously in original order, preserving all raw lump bytes and eight-byte names. No geometry normalization or texture assembly is needed for this phase; original on-disk little-endian layouts are the frozen binary ABI. `schemas/wad-layouts-v1.json` lists map record fields in byte order. Coordinates remain signed int16 map units on disk; runtime loaders later widen to signed 16.16. Index fields are validated in original signed/unsigned domains from p_setup.c; `-1` side sentinel is preserved. BSP children are raw uint16, high bit=leaf and low15=index; validate references, cycles, and subsector seg spans. Reject malformed lengths, negative offsets/counts, out-of-bounds references and unsupported map layouts explicitly. Duplicate names and zero-length markers are valid; lookup follows original last matching name rule.

Validate THINGS, LINEDEFS, SIDEDEFS, VERTEXES, SEGS, SSECTORS, NODES, SECTORS, REJECT and BLOCKMAP for selected map E1M1. Also validate PLAYPAL, COLORMAP, PNAMES, TEXTURE1/2, referenced patches and flats with declared lengths/offsets. Preserve unknown lumps opaque. Texture definitions/patch posts stay original static data; no frame/view calculations are allowed. Assets tooling is TypeScript, executable under pinned Node's native type stripping with no dependency install required.

Pin a redistributable Freedoom release/archive/WAD SHA and license, provide a checksum-verified download command and deterministic pack command. Commit small selected-lump snapshots and identity metadata; full downloads/packages live in ignored artifacts/local. Derive palette variant0 as the existing palette-v0 JSON bound to real bundle identity. Browser remains a mock EVM frame display; selecting a real palette must not imply a real renderer.

## Integration ownership and acceptance

Integrator: this document, schemas, shared Solidity headers/adapter, main docs, verification scripts, resource-placement experiments and browser palette integration. Reference agent: tools/reference/** and test/fixtures/reference/**. Numeric/tables agent: src/doom/{m_fixed,tables}.sol, test/unit/{m_fixed,tables}.t.sol, tools/tables/**. Assets agent: tools/wad/** and test/fixtures/wad/**. Each uses a separate worktree and gitmoji commits. No edits outside assigned paths.

Final gates: native oracle reproducible; fixed math compared to it including edge/error domains; complete table checksums and lookups; real Freedoom deterministic parse/pack with malformed-input tests; storage-versus-code upload/sample-read measurements (frame-render measurements remain impossible before Phase 2); actual palette-to-Canvas check; every existing Phase 0 gate; updated source mapping, reproducible report and all F1 checklist items. No Phase 2 Solidity geometry, resource renderer adapters, BSP/segs/draw or real frame generation in this phase.
