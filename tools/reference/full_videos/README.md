## Original presentation sequence

A one-second original TITLEPIC establishes GS_DEMOSCREEN. The first gameplay
command is consumed before the original state-change melt. A blocking wipe
runs at deterministic one-tic/35Hz display steps and consumes no gameplay/demo
command. Original ST/HU are ticked in P/ST/HU order, using a separately retained
miscellaneous UI RNG stream so historical canonical DSG1 snapshots remain exact.
No gameplay RNG is changed. Original UI resources are borrowed outside the
native physical zone, matching the established Phase 4 consumer profile.

World captures use a memory copy as in the accepted observer, with view10 and
persistent ST/HU widget state/framebuffer. Saved gameplay digest is checked
before/after every presentation call. Render history is not committed into
gameplay; no full-process native allocator/render-history claim is made.

After original GA_COMPLETED, corresponding original G_DoCompleted takes its
statistics directly from saved authoritative game state. All remaining original
demo commands drive original WI/F tickers. E1M8 bypasses WI; E1M9 selects E1M4.
A separate zero-input UI continuation holds readable statistics or advances
E1 finale text to the original CREDIT art, including its forced second melt.
It never runs P_Ticker or loads a next level. The marker itself would quit native
single-demo mode; continuation is explicitly a presentation extension, not
additional demo data. No fake exit or host statistic is supplied.

Native verification replays a fresh gameplay prefix then renders once with
original ST/HU/view10. UI-only native runs retain original WI/F/wipe state and
consume the whole input tail. Native output is comparison-only; it never enters
EVM. Full pixels, palettes, column positions and RNG are checked in their declared
profile. Virtual pointer samples remain experimental even when numerically equal.

## Recovery, verification and media

```sh
node tools/reference/full_videos/record.mjs --map 1 --observer artifacts/local/full-videos/observer-v2 --output artifacts/local/full-videos/E1M1/pilot-v2 --resume
node tools/reference/full_videos/rollback.mjs artifacts/local/full-videos/E1M1/pilot-v2
python3 tools/reference/full_videos/encode.py artifacts/local/full-videos/E1M1/pilot-v2
python3 tools/reference/full_videos/verify-ui.py artifacts/local/full-videos/E1M1/pilot-v2
python3 tools/reference/full_videos/verify.py artifacts/local/full-videos/E1M1/pilot-v2
python3 tools/reference/full_videos/telemetry.py artifacts/local/full-videos/E1M1/pilot-v2
```

Each checkpoint streams Anvil's compressed state into a separate file and
atomically publishes source/input/ABI/resource/budget identity, report and hashes.
Resume refuses identity drift, checks all saved frame hashes, resources,
contract runtime, canonical snapshot and frame counter. Receipts are compressed
individually and retained with hashes. SIGINT/SIGTERM requests a recoverable stop
at the next completed original/UI tic. `--stop-after-tic` is an explicit partial
checkpoint, never a full video. New attempts use new directories. Source fixes
requiring a changed contract retain the old failed attempt and replay authentic
inputs from startup; they never inject a saved native world or bypass guards.

Encoding performs per-frame original palette decoding, nearest 1280×960 scaling,
35 FPS H.264 CRF16 and MP4 assembly only. Both clocks use 35000 units/second;
FFprobe checks every packet PTS/duration, resolution, 4:3 aspect and frame count.
H.264 is lossy; exact pixels live in indexed8 evidence. Existing MP4s are never
overwritten. All videos, commercial WAD/frames/resources and full receipts stay
in ignored local artifacts; commit tools, hashes, manifests and reports only.

Do not start the other eight EVM recordings until the complete pilot passes
native gameplay/UI/wipe, storage/rollback, input and final media gates. At most
two independent recording jobs should run in parallel after pilot acceptance.

## Publication telemetry

`telemetry.py` derives per-map JSON and an aggregate JSON from receipts, frame
manifests, RPC timings, source bindings and FFprobe. Count gameplay, menu, wipe,
WI and finale frames separately; Status Bar coverage overlaps gameplay/wipe
categories. Gas is grouped only by actual transaction boundaries. World/status/
HUD gas within a capture is unavailable separately. UTC elapsed windows, RPC
transaction/render intervals and resumed downtime are clearly distinguished.
No CPU-time, model-cost or gas subdivision is estimated. Preserve failed attempts
and report their costs separately from successful final recordings.
